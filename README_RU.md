# Push-Swap

Две CLI-программы на Go для сортировки целых чисел ограниченным набором операций над двумя стеками. `push-swap` генерирует последовательность операций, а `checker` выполняет её и проверяет результат.

Для маленьких входов solver использует точный поиск, для больших — LIS-based стратегию. Product code использует только стандартную библиотеку Go.

## 🚀 Быстрый старт

### Требования

- Go `1.21+`
- Git
- Bash; на Windows используется Git Bash

### Клонирование

```bash
git clone https://01.tomorrow-school.ai/git/nyestaye/push-swap
cd push-swap
```

### Сборка

Одни и те же команды работают в Bash на Linux/macOS и в Git Bash на Windows:

```bash
go build ./cmd/checker
go build ./cmd/push-swap
```

На Linux/macOS Go создаёт `checker` и `push-swap`, на Windows — `checker.exe` и `push-swap.exe`.

### Запуск

В примерах ниже используются имена бинарников Linux/macOS. В Git Bash на Windows достаточно добавить `.exe`.

```bash
./push-swap "2 1 3 6 5 8"
```

Проверка сгенерированной последовательности:

```bash
ARG="4 67 3 87 23"
./push-swap "$ARG" | ./checker "$ARG"
```

Ожидаемый результат:

```text
OK
```

## 📝 О проекте

В задании используются два стека:

- `A` изначально содержит входные числа; первое число находится наверху;
- `B` изначально пуст;
- конечное состояние — `A` отсортирован по возрастанию, `B` пуст.

`push-swap` может выводить только разрешённые операции, по одной на строку. `checker` читает их из stdin и печатает `OK`, если конечное состояние корректно, иначе `KO`.

Некорректные числа, дубликаты, неизвестные операции и неправильный формат checker input приводят к `Error` в stderr. При отсутствии аргументов обе программы ничего не выводят.

## 🎛️ Операции

В задании определено ровно 11 операций:

- `pa`, `pb` — перенести верхний элемент из одного стека в другой;
- `sa`, `sb`, `ss` — поменять местами два верхних элемента одного или обоих стеков;
- `ra`, `rb`, `rr` — прокрутить один или оба стека вперёд;
- `rra`, `rrb`, `rrr` — прокрутить один или оба стека назад.

Если в стеке недостаточно элементов, операция просто не меняет его состояние.

## 🧠 Стратегия сортировки

### 2–3 элемента

Для маленьких прямых случаев используются короткие заранее заданные последовательности.

### 4–6 элементов

Solver выполняет breadth-first search по полному state space двух стеков после преобразования значений в относительные ранги. Для шести значений полный state space содержит всего `7 × 6! = 5040` состояний, поэтому BFS возвращает кратчайшую допустимую последовательность для этих размеров.

### 7+ элементов

Для больших входов используется LIS-based стратегия:

1. значения преобразуются в ранги;
2. вычисляется Longest Increasing Subsequence;
3. элементы LIS остаются в `A`, остальные отправляются в `B`;
4. элементы из `B` возвращаются в наиболее дешёвую позицию вставки;
5. совместимые вращения объединяются через `rr` и `rrr`;
6. минимальный элемент поворачивается наверх.

Этот путь оптимизирован под лимиты задания, но не заявляет глобально минимальную последовательность для произвольного размера.

## ✅ Checker

Известный `KO`-кейс из audit:

```bash
echo -e "sa\npb\nrrr\n" | ./checker "0 9 1 8 2 7 3 6 4 5"
```

```text
KO
```

Известный `OK`-кейс:

```bash
echo -e "pb\nra\npb\nra\nsa\nra\npa\npa\n" | ./checker "0 9 1 8 2"
```

```text
OK
```

Парсинг инструкций строгий: каждая операция должна точно совпадать с одной из 11 разрешённых команд и завершаться newline.

## 🧪 Тесты и audit

Полный набор тестов:

```bash
go test ./... -count=1
```

Статические проверки:

```bash
go vet ./...
gofmt -l $(find . -name '*.go' -type f)
```

Executable-кейсы из audit-листа 01-edu собраны в `tests/audit_test.go` и запускаются отдельно одной командой:

```bash
go test ./tests -run '^TestAudit_' -count=1 -v
```

Этот suite покрывает официальные no-output и error cases, checker `OK` / `KO`, `push-swap | checker`, лимит `< 9` для six-number case, `< 12` для five-number cases, `< 700` для 100 чисел и требование использовать только стандартную библиотеку Go.

Дополнительное покрытие solver включает:

- все перестановки размеров `2..6`;
- все `5040` перестановок размера `7` через large-solver path;
- разные большие размеры;
- `500` детерминированных перестановок по 100 элементов с повторным выполнением каждой последовательности для проверки корректности;
- structured 100-element cases: reverse, rotated и zigzag.
